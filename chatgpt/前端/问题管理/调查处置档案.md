## ENV-FE-001：PowerShell 禁止运行 `npm.ps1`

- 发现时间：2026-08-14
- 发现环境：Windows PowerShell；Node.js 安装在 `D:\software\node`
- 用户可见现象：`node --version` 正常，但 `npm --version` 返回 `PSSecurityException`
- 最小复现步骤：在 PowerShell 中执行 `npm --version`
- 期望结果：显示 npm 版本
- 实际结果：PowerShell 优先解析 `D:\software\node\npm.ps1` 并因执行策略拒绝运行
- 证据：`Get-Command npm -All` 同时发现 `npm.ps1`、`npm.cmd` 和无扩展名入口
- 影响范围：只影响 PowerShell 中的命令解析；Node.js 和 npm 安装本身正常
- 根因：命令解析优先选择 PowerShell 脚本，而当前环境不允许执行该 `.ps1`
- 候选方案与取舍：修改 ExecutionPolicy 可恢复 `npm` 简写，但会改变本机安全策略；直接使用
  `npm.cmd` 不改变策略且满足开发需要
- 确认方案：使用 `npm.cmd` 和 `npx.cmd`
- 修改内容：未修改系统策略和项目代码
- 回归结果：`npm.cmd --version` 返回 `11.16.0`；Vite 模板依赖安装、审计和开发服务器启动成功
- 当前状态：已验证

## CONTRACT-F2-001：重复文档上传策略未冻结

- 发现时间：2026-08-18
- 发现环境：设计 F2 单文件上传、历史文档列表和上传重试流程
- 用户可见现象：相同内容可以使用相同或不同文件名重复上传，产生两条文档、两份存储和后续重复解析
- 最小复现步骤：连续上传同一文件，或复制并修改文件名后再次上传
- 期望结果：明确同名、同内容、相似内容、网络重试和跨用户重复分别怎样处理
- 实际结果：后端已按 `(owner_user_id, sha256)` 原子创建或返回已有记录；首次上传返回
  `201 + duplicate:false`，同用户重复内容返回 `200 + duplicate:true`，不同用户仍各自创建独立记录
- 证据：`docs/backend/architecture/document-upload-deduplication.md`、
  `docs/shared/api/http-api-overview.md` 和提交 `2224984 feat: deduplicate document uploads per user`
- 影响范围：F2 可以稳定区分新建与重复成功；不再阻塞上传前端开发
- 根因：数据库初版只保存哈希但没有冻结个人用户产品策略，现已由后端应用服务和数据库唯一约束补齐
- 候选方案与取舍：允许重复最简单但浪费存储和计算；前端单独计算哈希只能提示且对 200 MiB 文件成本高；
  后端按 OwnerScope 拒绝精确重复可以并发收口，但需要处理已有重复数据和明确是否允许强制上传
- 确认方案：第一版在同一用户内阻止精确字节重复；文件名不参与判断；相似内容不自动去重；跨用户不共享记录
- 最终契约：重复不是异常，返回已有文档的 `200 + duplicate:true`；前端提示“该内容已存在”并刷新列表
- 并发约束：数据库使用 `(owner_user_id, sha256)` 唯一约束作为最终裁判，前端不承担并发正确性
- 前端策略：上传中禁用重复提交；不按文件名拒绝；同时校验 HTTP 状态和 `duplicate` 字段；重复结果保留原名称与 ID
- 修改内容：建立文档模型、运行时 DTO 校验、分页列表、上传状态和重复提示；同步正式路线与本地记录
- 回归结果：后端并发与真实 HTTP 测试已通过；前端 10 个测试文件 30 个测试、类型、Lint、格式和构建通过；
  真实浏览器重复上传待本地服务环境启动后执行
- 当前状态：已验证

- 修改内容：F2-B 已接入详情、创建解析任务、任务轮询、文档状态刷新、chunks 和删除保护
