## 当前前端专项分工

- 用户当前参与架构、核心逻辑、产品流程和设计方向确认，不承担代码书写；
- Codex 在用户明确授权实现后负责前端骨架、业务代码、测试、文档同步和验证；
- 开始每段工作前仍需按共享协议说明当前工作、目的、路线位置、输入输出、完成标准和非目标；
- 架构选择明显影响后续成本时先讨论，未授权时不因模板已存在就继续编写业务代码。

## 已确认方向

- Vue 3 Composition API + TypeScript + Vite；
- Vue Router、轻量 Pinia、Axios API 层；
- Element Plus 选择性使用，页面视觉保持简约、类 Codex、内容优先；
- 轻量 Feature-first 模块化；
- Vitest + Vue Test Utils，Playwright 后置到 F5；
- ESLint + Prettier 作为工程规范；
- 当前不采用 Nuxt、SSR、微前端、GraphQL 或复杂设计系统。

## 独立记录

- 每个开发日收尾固定形成两份记录：`复盘/` 的“学习与架构复盘”和 `进度/` 的“开发进度与计划对照”；
- 学习与架构复盘记录学到的知识、完整数据流、分层责任、设计取舍、测试认识和仍需练习的内容；
- 开发进度与计划对照记录项目当前里程碑、理想目标、当日变化、验证证据、剩余差距和下一步；
- 用户在对话中提出可长期复用的前端知识或架构问题时，及时把问题和回答追加到 `知识库/问题.md`；
- 真实 Bug、联调异常、契约缺口和文档不一致才进入 `问题管理/`，不把普通学习提问登记为 Bug；
- 可用性、页面性能和端到端验收资料写入 `评估/`。

后端历史不会复制进来；跨端信息通过正式 API 契约连接。
