# P4 带来源问答质量评估计划

## 1. 当前工作与核心目的

本计划评估 `POST /answers` 第一版是否能够根据检索证据形成可追踪回答。它不是新的 HTTP 接口，
也不修改检索、Prompt 或模型参数。当前先固定问题、评价字段和执行顺序，再运行真实远程调用，避免
看过答案以后临时改变问题或标准。

本阶段需要区分四个对象：

```text
用户问题
  → 检索命中的候选证据 sources
  → 模型在答案中实际使用的引用标记 [1]、[2]……
  → 每个事实性结论是否真的被对应证据支持
```

`sources` 只是实际交给模型的候选文本块，不能自动证明回答正确。

## 2. 第一版评价范围

冻结样本至少覆盖：

1. 中文问题、中文文献；
2. 英文问题、英文文献；
3. 中文问题、英文文献的跨语言回答；
4. 不限定文档的多文献问题；
5. 文献中没有答案、应明确拒答的问题；
6. 文档尚未生成向量、应走零证据降级的问题；
7. 与磁浮无关的负对照文献，防止只在单一主题上评价。

第一版继续使用默认 `top_k=5`。如需比较 Top K，必须保留原始结果并作为独立实验，不得覆盖基线。

## 3. 三层评价指标

### 3.1 工程正确性

| 指标 | 含义 |
|---|---|
| HTTP 状态 | 请求是否成功或返回预期错误 |
| 响应结构 | `answer`、`sources`、`usage` 是否符合契约 |
| 引用编号合法 | 答案中出现的 `[N]` 是否都位于 `1..len(sources)` |
| 资源降级 | 零证据时是否 `sources=[]`、Token 为 0、没有调用生成模型 |
| 延迟和 Token | 记录端到端耗时以及 prompt/completion/total token |

工程正确性可以自动检查，但不能替代人工事实核对。

### 3.2 检索证据质量

人工阅读每条 source，按下面标准评分：

| 分数 | 含义 |
|---:|---|
| 0 | 与问题无关，不能帮助回答 |
| 1 | 主题相关或提供局部背景，但不能直接支持主要结论 |
| 2 | 直接包含回答问题所需的事实、方法或结论 |

同时记录预期文档是否出现、同一文档是否挤占全部 Top K，以及 PDF 解析噪声是否影响证据可读性。

### 3.3 答案与引用一致性

把答案拆成可以独立核对的事实性结论，再逐条检查：

| 检查项 | 判断方法 |
|---|---|
| 引用存在 | 事实性结论后是否有 `[N]` |
| 引用可定位 | `[N]` 是否对应返回的 source |
| 引用支持 | source 是否直接或合理地支持该结论 |
| 无证据扩写 | 模型是否加入 sources 中没有出现的具体数字、方法或因果关系 |
| 语言匹配 | 回答的主要语言是否与用户问题一致 |
| 安全拒答 | 证据不足时是否明确说明不足，而不是猜测 |

人工总评使用：

```text
2 = 主要结论均有证据支持，可以直接帮助用户
1 = 部分可用，但存在证据缺口、遗漏或语言问题
0 = 回答与证据明显不一致、严重答非所问或应该拒答却编造
```

## 4. 执行协议

1. 执行前冻结问题、文档范围、预期行为和评价标准；
2. 保存每次请求体、原始响应、HTTP 状态、耗时和 Token；
3. 先做自动结构检查，再做 source 相关性人工评分；
4. 最后把答案拆成事实性结论，核对结论与引用；
5. 失败案例不得删除，也不能只改写问题后重新计为成功；
6. 模型、Prompt、Top K 或语料变化后必须建立新的评估批次；
7. 实际应用或测试中发现的非预期问题按统一 Bug 协议实时登记，不能边测边静默修复。

本机冻结问题集、原始响应和人工评分表保存在 Git 忽略的
`chatgpt/检索评估/2026-08-13/`。项目仓库只保存不含论文正文和密钥的评价方法与阶段结论。

## 5. 第一轮完成标准

第一轮样本较小，只建立基线，不宣称生产级准确率。硬性检查为：

- 所有响应结构符合 HTTP 契约；
- 所有引用编号均在来源范围内；
- 零证据样本不产生远程生成 Token；
- 应拒答案例不编造具体事实；
- 英文问题的语言不一致问题必须保留并统计；
- 所有失败和质量问题都有原始证据及问题编号。

检索证据分数、事实支持分数和延迟只做如实报告，不为了达到预设数字临时修改测试集。

## 6. 当前非目标

- 不开发自动事实核验模型；
- 不引入 LangChain、rerank 或混合检索；
- 不修改数据库 schema；
- 不处理 PDF 公式和字体映射问题；
- 不把模型自报的“有引用”当作可信评价结果；
- 不在本轮建立公开排行榜或跨模型优劣结论。

## 7. 后续决策依据

完成第一轮后，根据失败类型再决定下一步：

- source 本身无关：优先改检索、来源去重或 rerank；
- source 有答案但模型没利用：优先改 Prompt 或生成模型；
- 引用编号越界：增加答案后处理和引用合法性校验；
- 证据不足仍编造：加强拒答规则或增加支持度门禁；
- 只有语言不匹配：单独调整回答语言约束；
- PDF 文本不可读：回到 PDF-4 质量门禁，不在 RAG 层猜测修复原文。
