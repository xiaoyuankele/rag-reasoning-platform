## 2. 冻结的接口契约

请求：

```http
POST /documents
Content-Type: multipart/form-data
Cookie: rag_session=...

file=<单个 PDF、Markdown 或 TXT 文件>
```

首次上传成功：

```text
HTTP 201 Created
duplicate = false
```

同一用户再次上传字节内容完全相同的文件：

```text
HTTP 200 OK
duplicate = true
```

两个响应都返回平铺的文档字段，包括 `id`、`title`、`original_name`、`mime_type`、`size_bytes`、
`sha256`、`status`、`error_message`、`created_at` 和 `updated_at`。重复响应来自第一次上传的记录，
因此 `original_name` 可能与本次选择的文件名不同。

不同用户上传相同内容不算重复：每个用户各自得到 `201 + duplicate:false` 和独立文档。前端不提交
`user_id`，身份只来自 HttpOnly Session Cookie。

## 3. 前端对应关系

| 后端结果                      | 前端处理                                                           |
| ----------------------------- | ------------------------------------------------------------------ |
| `201 + duplicate:false`       | 显示“上传完成”，刷新第一页并高亮新记录                             |
| `200 + duplicate:true`        | 显示“该内容已存在”，展示本次文件名和已有文档名，刷新并高亮已有记录 |
| 状态与 `duplicate` 不匹配     | 作为 `invalid-response`，防止契约漂移                              |
| `413`                         | 提示超过服务端上传上限                                             |
| `415`                         | 提示仅支持合法 PDF、Markdown 或纯文本                              |
| `400`                         | 提示选择内容有效的文件                                             |
| `401 authentication_required` | 复用全局会话失效流程                                               |

前端不能按文件名或浏览器自行计算结果决定是否重复；SHA-256、所有者范围和并发唯一性都由后端负责。

## 7. 2026-08-20 已接入：上传前预检

本文件冻结的 `POST /documents` 契约继续有效。前端已使用 Web Worker 分块计算 SHA-256，并调用正式
`POST /documents/preflight`；浏览器摘要只用于请求后端检查，前端不能仅凭本地摘要自行声明数据库中已有文档。

预检命中会跳过文件正文上传；未命中后仍调用本文的上传接口，后端继续重新计算摘要并由数据库唯一约束处理并发竞争。
网络、超时和 5xx 可降级上传，400、401、413 不得绕过。正式数据流、哈希实现和验收清单见
[F2 上传前重复文件预检](f2-upload-preflight-evaluation.md)。
