# 前端分层与阶段路线

## 1. 核心目的

为文档上传、处理状态、检索和带来源问答提供一个轻量、可理解、可测试的用户界面，
同时避免页面组件直接耦合后端 JSON 和 HTTP 细节。

## 2. 已确认分层

```text
页面/路由
  ↓ 组合功能
功能模块（文档、检索、问答）
  ↓ 调用
应用状态与用例
  ↓ 使用
API Client + DTO 转换
  ↓ HTTP
Go 后端
```

- 页面与组件：负责展示和用户交互；
- 功能模块：围绕“上传文档”“搜索”“提问”等用户动作组织；
- 状态与用例：管理加载、成功、空结果和失败状态；
- API Client：唯一负责 URL、请求方法、请求体和响应解析；
- DTO/类型转换：隔离后端契约与前端视图模型；
- 测试：优先验证用户行为和错误状态，不复制后端内部实现。

具体目录、依赖方向、状态归属、技术栈和测试策略见
[前端应用架构](frontend-application-architecture.md)。

## 3. 分阶段路线

- `F0` 技术栈与工程骨架：确定框架、构建工具、格式化、测试与目录；
- `F1` API 基础：建立统一 Client、环境配置、错误模型和健康检查；
- `F2` 文档管理：上传、列表、详情、删除、解析任务状态；
- `F3` 检索：关键词检索、筛选、分页、来源与页码展示；
- `F4` AI 能力：语义检索、带来源问答、加载/超时/费用提示；
- `F5` 工程化：端到端测试、可访问性、性能、构建和部署。

## 4. 第一阶段非目标

- 不先实现复杂设计系统；
- 不把所有后端接口一次性接完；
- 不在页面组件里散落 `fetch` 调用；
- 不在前端复制 Go 的领域规则；
- 不默认启用会产生远程模型费用的能力；
- 不实现登录、注册、成员管理和租户切换；前端第一版服务于单个个人工作区。

## 5. F0 完成标准

技术栈经讨论确认，目录骨架可运行，能显示一个页面，能通过统一 API Client 请求
`GET /health`，并具有最小自动化测试。

- [x] 确认 Composition API、Feature-first 分层与简约研究工作台方向；
- [x] 使用官方 Vue + TypeScript 模板创建 `web/`；
- [x] 安装模板依赖并启动 Vite 开发服务器；

因此，F0 已于 2026-08-14 完成。下一阶段进入 F1，继续扩展 API 基础与契约转换能力。

- [x] 统一 Client、环境配置、超时和安全错误模型已经由健康检查与搜索共同复用；
- [x] 为 `GET /search` 增加运行时 DTO 校验和 snake_case 到 camelCase 转换；
- [x] 搜索词、可选文档 ID 和页码通过 Router query 保存，可刷新和返回；
- [x] 完成加载、结果、空数据、失败、重试和上一页/下一页状态；
- [x] 显示来源文档、MIME 类型、页码、文本块序号和原始内容；
- [x] 自动化测试、生产构建和真实 HTTP 成功/失败联调通过；
- [ ] F2 文档管理完成后，把临时数字文档 ID 输入替换为文档选择器；
- [ ] 语义检索继续留在 F4，不与免费关键词检索混合触发。

F1 API 基础至此完成。F3 的基础关键词检索已经可用，但完整检索工作台仍等待 F2 文档选择能力，
因此 F3 状态为“最小可用切片完成，持续完善”。

## 7. 与后端 P5、未来 P6 的关系

- 后端 `P5` 负责运行路径、配置、日志、部署、备份和可观测性，不等于前端开发；
- 前端继续独立推进 `F0～F5`，并在 F1 建立稳定 API 边界后接入现有个人版后端；
- 用户认证、工作区和多租户属于未来 `P6`。P6 启动前，前端不能自行伪造 `user_id`，也不能只在
  界面上隐藏数据来假装实现权限；身份必须由后端认证，数据隔离必须在 Application 与 Repository 生效。

完整阶段边界与执行顺序见
[产品演进路线](../../shared/architecture/product-evolution-roadmap.md)。
