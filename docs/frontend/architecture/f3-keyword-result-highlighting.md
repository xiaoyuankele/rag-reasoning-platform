# F3 关键词检索结果高亮

> 状态：2026-08-19 已实现。高亮是前端展示增强，不改变 `GET /search` 的检索、排序和分页语义。

## 1. 当前数据边界

后端关键词接口以文本块为命中单位，返回 `content`、来源文档、页码和文本块序号。前端不重新执行检索，只使用响应中的
规范化 `query` 在每个 `content` 中标记全部命中位置。因此高亮不会改变命中数量、分页总数或 OwnerScope。

```text
GET /search
→ KeywordSearchPage(query, results)
→ KeywordSearchResultCard(hit, query)
→ 普通文本片段 + <mark>命中片段
```

## 2. 安全与匹配规则

- 文档正文继续通过 Vue 文本插值渲染，不使用 `v-html` 或 `innerHTML`；
- 查询词中的 `+`、`(`、`[` 等正则特殊字符按普通文本处理；
- 英文大小写不同仍可以高亮，并标记文本块中的全部连续命中；
- 页面保留后端返回的原文和空白，不用高亮后的文本替换数据模型；
- 高亮颜色使用统一设计变量，正文颜色和可复制文本不变。

## 3. “只返回文本块”的后续演进

文本块是当前检索接口的正式结果单位，适合快速定位证据。若需要阅读更完整上下文，后续应增加“查看来源”交互，并由后端
提供以 `chunk_id` 为中心的相邻文本块或原文定位契约。前端不应仅凭当前分页结果猜测前后文，也不应把整篇 PDF 下载到
浏览器后自行搜索。

## 4. 验证

- 单元测试覆盖多次命中、英文大小写、正则特殊字符和无命中；
- 组件测试确认真实结果渲染 `<mark>`；
- 类型检查、Lint、格式检查、完整测试和生产构建纳入常规门禁。
