# 前端应用架构

> 确认日期：2026-08-14。当前位于 F0 联调收尾，本文记录已经共同确认并实施的架构方向；
> 未安装或未验证的能力会明确标记，不把计划描述成现状。

## 1. 产品与架构目标

前端为文档上传、异步处理、关键词/语义检索和带来源问答提供一个简洁、专业、可测试的研究工作台。
它采用单页应用，不承担后端领域规则，也不把远程模型能力包装成默认可用的本地功能。

```text
浏览器
  ↓
Vue 单页应用
  ↓
前端功能模块与状态
  ↓
统一 API Client + DTO 转换
  ↓ HTTP JSON
Go 后端
  ↓
PostgreSQL / Python / 远程模型
```

## 2. 技术栈决策与当前状态

| 能力 | 选择 | 当前状态 | 采用原因 |
|---|---|---|---|
| UI 框架 | Vue 3 Composition API + `<script setup>` | 已安装，模板可运行 | 类型友好、组件化清晰、适合中型工作台 |
| 开发语言 | TypeScript | 已安装，模板可构建 | 约束 API DTO、状态和组件边界 |
| 构建工具 | Vite | 已安装，开发服务器已验证 | 开发反馈快，配置轻量 |
| 页面路由 | Vue Router | 已安装并接入，四个基础路由可构建 | 映射工作台、文档库、搜索和问答页面 |
| 跨页面状态 | Pinia | 已安装并注册，尚无全局 Store | 只承载真正跨页面共享的状态 |

## 3. 模块架构

采用轻量 Feature-first 结构，借鉴按业务能力组织代码的思想，但不机械照搬完整
Feature-Sliced Design。

```text
web/src/
├─ app/                       # 应用启动、插件注册、Router、全局样式
├─ pages/                     # 路由页面，只组合功能模块
├─ features/
│  ├─ system-health/           # 健康检查、连接状态与重试
│  ├─ documents/              # 上传、列表、详情、处理、删除
│  ├─ search/                 # 关键词和语义检索
│  └─ answer/                 # 问答、回答语言、引用来源
├─ entities/
│  ├─ document/               # 文档及展示模型
│  ├─ processing-job/         # 解析任务与状态
│  └─ answer-source/          # 回答来源与页码
└─ shared/
   ├─ api/                    # Axios 实例、错误模型、基础请求能力
   ├─ ui/                     # 与业务无关的通用展示组件
   ├─ styles/                 # 设计令牌、基础样式、主题变量
   └─ utils/                  # 纯格式化和通用工具
```

依赖方向保持单向：

```text
app → pages → features → entities → shared
```

- `pages` 不直接编写 HTTP 细节；
- `shared` 不反向依赖具体业务；
- 一个功能需要另一个功能时由页面或应用层组合，不任意交叉导入；
- 后端 DTO 与前端视图模型即使字段相似，也通过 API/转换边界隔离。

## 4. 状态归属

前端状态按最小共享范围保存：

| 状态范围 | 放置位置 | 示例 |
|---|---|---|
| 单个组件 | 组件本地状态 | 弹窗开关、输入框、按钮 loading |
| 单个功能流程 | feature composable/use case | 上传、任务轮询、单次搜索 |
| 跨页面共享 | Pinia | 当前文档范围、后端能力状态、用户界面偏好 |
| 可恢复 URL 状态 | Vue Router query/params | 搜索词、页码、文档 ID |

单次搜索结果、临时上传进度和局部错误默认不进入全局 Store。

## 5. HTTP 与契约边界

- 所有 URL、方法、超时和响应解析统一进入 API Client；
- 功能模块不能散落 `fetch` 或 Axios 配置；
- TypeScript 类型不能替代运行时 HTTP 状态检查；
- 前端根据状态码与稳定契约处理错误，不展示后端内部异常；
- DTO 转换负责处理 `snake_case`、可空字段、时间字符串和视图兜底；
- 权威接口契约位于 `docs/shared/api/`，前端类型必须随契约变更同步；
- 语义检索和回答可能产生远程调用，界面必须提供加载、超时、重试与功能关闭状态。

当前开发环境约定：浏览器请求以 `/api` 为基础路径，Vite 开发代理将其转发到默认
`http://localhost:8080` 并移除 `/api` 前缀。生产环境仍需由部署层提供同源反向代理，
或通过 `VITE_API_BASE_URL` 配置实际 API 地址。

## 6. 页面与视觉结构

第一版采用桌面优先的研究工作台：

```text
左侧导航 / 文档范围
        ↓
中间主工作区：文档库、搜索或问答
        ↓
按需出现的右侧来源面板
```

视觉基线为简约、克制、专业、内容优先：中性色、细边框、充分留白、少阴影和少量语义色。
Element Plus 只用于弹窗、分页、选择器、消息等行为成熟的组件；页面框架、文档列表、答案和来源区域
保持项目自己的视觉表达。

## 7. 测试与质量策略

```text
类型检查
  → API/状态纯函数测试
  → 组件和 composable 行为测试
  → 页面集成测试
  → 真实后端端到端测试
```

- Vite 负责转换和构建，类型检查必须由 `vue-tsc` 单独执行；
- Vitest 验证状态转换、错误转换和纯逻辑；
- Vue Test Utils 验证组件渲染和用户交互；
- Playwright 在 F5 验证上传、处理、搜索和问答主流程；
- 测试优先断言用户可观察结果，不依赖组件内部实现细节。

## 8. 当前非目标

- Nuxt、SSR 和 SEO 架构；
- 微前端、跨端框架和多包工作区；
- GraphQL 或替换现有 REST 契约；
- 完整照搬大型 FSD/DDD 前端规则；
- 自建通用组件库；
- 把所有数据放入 Pinia；
- 为简历而提前引入未被真实需求使用的技术。
