# 前端应用架构

> 确认日期：2026-08-14，架构优化对齐日期：2026-08-21。F0 工程骨架与真实健康检查联调已经完成，
> 本文记录已经共同确认的架构方向；
> 未安装或未验证的能力会明确标记，不把计划描述成现状。

## 1. 产品与架构目标

前端为文档上传、异步处理、关键词/语义检索和带来源问答提供一个简洁、专业、可测试的研究工作台。
它采用单页应用，不承担后端领域规则，也不把远程模型能力包装成默认可用的本地功能。项目升级为高性能、高并发工程训练型
模块化单体后，前端负责有界请求、背压反馈、可观察状态和端到端体验指标，但不复制后端 Worker、数据库任务队列或资源调度。

```text
浏览器
  ↓
Vue 单页应用
  ↓
前端功能模块与状态
  ↓
统一 API Client + DTO 转换
  ↓ HTTP JSON
Go 后端
  ↓
PostgreSQL / Python / 远程模型
```

## 3. 模块架构

采用轻量 Feature-first 结构，借鉴按业务能力组织代码的思想，但不机械照搬完整
Feature-Sliced Design。

```text
web/src/
├─ app/                       # 应用启动、插件注册、Router、全局样式
├─ pages/                     # 路由页面，只组合功能模块
├─ features/
│  ├─ system-health/           # 健康检查、连接状态与重试
│  ├─ auth/                    # P6 注册、登录、退出、登录态恢复和密码重置
│  ├─ documents/              # 哈希预检、批量导入、列表、详情、处理、删除
│  ├─ embeddings/             # 单篇/批量向量任务、最近任务发现、集中轮询和取消
│  ├─ search/                 # 短语与同一 chunk 多关键词检索
│  └─ answer/                 # 单次问答、回答语言、引用来源和 Token 用量
├─ entities/
│  ├─ document/               # 文档及展示模型
│  ├─ user/                   # P6 当前用户公开模型与 DTO 转换
│  ├─ processing-job/         # 解析任务与状态
│  ├─ embedding-job/          # 向量任务、状态和可取消规则
│  └─ answer/                 # 回答、来源、页码与用量模型
└─ shared/
   ├─ api/                    # Axios 实例、错误模型、基础请求能力
   ├─ ui/                     # 与业务无关的通用展示组件
   ├─ styles/                 # 设计令牌、基础样式、主题变量
   └─ utils/                  # 纯格式化和通用工具
```

依赖方向保持单向：

```text
app → pages → features → entities → shared
```

- `pages` 不直接编写 HTTP 细节；
- `shared` 不反向依赖具体业务；
- 一个功能需要另一个功能时由页面或应用层组合，不任意交叉导入；
- 后端 DTO 与前端视图模型即使字段相似，也通过 API/转换边界隔离。

## 4. 状态归属

前端状态按最小共享范围保存：

| 状态范围        | 放置位置                    | 示例                                        |
| --------------- | --------------------------- | ------------------------------------------- |
| 单个组件        | 组件本地状态                | 弹窗开关、输入框、按钮 loading              |
| 单个功能流程    | feature composable/use case | 上传、任务轮询、单次搜索                    |
| 跨页面共享      | Pinia                       | P6 当前认证用户、后端能力状态、用户界面偏好 |
| 可恢复 URL 状态 | Vue Router query/params     | 搜索词、页码、文档 ID                       |

单次搜索结果、临时上传进度和局部错误默认不进入全局 Store。

向量化页面同样遵守最小状态范围：文档选择、逐项结果、最近任务快照和活动任务轮询保存在
`features/embeddings` composable，不进入 Pinia，也不写入文档库组件。页面初始化把当前 OwnerScope 的 document IDs
按最多 100 项分批提交给最近任务发现接口，只对 waiting/queued/processing 按 job ID 继续轮询。`job:null` 和发现失败
分别显示“无任务”和“状态未知”；最近 succeeded 不证明 embeddings 匹配当前 document revision。

关键词检索已经按此规则实现：完整短语的 `q`，或多关键词的重复 `term`、`operator`、`within`，连同
`document_id` 和 `page` 保存在 Router query 中，
单次请求的加载、结果、空状态和错误保存在 `features/search` composable 中，不进入 Pinia。F2-C 通过共享
`DocumentScope` 把缺省 ID 映射为“全部文档”、单个 ID 映射为“指定单篇”；范围选择器分页读取当前用户文档并只展示
解析 `ready` 项。页面层负责组合文档选择与检索，具体边界见
[F2-C 单篇 / 全部文档检索范围选择器](f2c-document-scope-picker.md)。

语义检索沿用相同的 `DocumentScope`，但只在 `/search?mode=semantic` 的显式提交中使用。问题正文和单次结果不写入 URL、Pinia
或浏览器持久化；`features/search` 内的 semantic API、composable 与 UI 独立于关键词分页状态，也独立于问答来源 DTO。
语义请求使用 30 秒超时，并复用共享容量错误与手动重试冷却；模式切换只负责页面组合，不会让两个检索流程互相自动触发。
具体边界见 [F4 语义检索前端交接](f4-semantic-search-handoff.md)。

## 5. HTTP 与契约边界

- 所有 URL、方法、超时和响应解析统一进入 API Client；
- 功能模块不能散落 `fetch` 或 Axios 配置；
- TypeScript 类型不能替代运行时 HTTP 状态检查；
- 前端根据状态码与稳定契约处理错误，不展示后端内部异常；
- DTO 转换负责处理 `snake_case`、可空字段、时间字符串和视图兜底；
- 权威接口契约位于 `docs/shared/api/`，前端类型必须随契约变更同步；
- 语义检索和回答可能产生远程调用，界面必须提供加载、超时、重试与功能关闭状态。

带来源问答已经按该边界实现：`AnswerPage` 只组合共享文档范围与 `GroundedAnswerPanel`；`features/answer` 分为 API、model、UI，
`entities/answer` 保存与 HTTP DTO 解耦的回答模型。问题不会写入 URL、Pinia 或浏览器持久存储；只有用户显式提交才调用
`POST /answers`。问答请求使用独立 70 秒超时覆盖远程生成窗口，其余 API 继续使用基础 Client 的 10 秒超时。

语义检索也已按同一原则实现，但不会复用问答请求或答案模型：`SearchPage` 组合关键词/语义模式，semantic feature 独立调用
`POST /semantic-search` 并运行时转换命中结果；只有显式提交才可能产生在线 Embedding 调用。

当前开发环境约定：浏览器请求以 `/api` 为基础路径，Vite 开发代理将其转发到默认
`http://localhost:8080` 并移除 `/api` 前缀。生产环境仍需由部署层提供同源反向代理，
或通过 `VITE_API_BASE_URL` 配置实际 API 地址。

P6 使用服务端 Session Cookie。前端不读取 Cookie 内容、不保存密码或 Session Token，也不向业务 DTO
附加 `user_id`。应用启动先调用 `/users/me` 恢复身份；公共登录页和受保护应用外壳根据三态认证状态
`unknown/authenticated/anonymous` 决定渲染，统一 API 错误层依据稳定 401 code 处理会话失效。
忘记密码成功后后端会撤销该用户全部旧 Session 并返回 `204`；前端必须进入匿名状态并要求使用新密码登录，
不能把密码重置误当成一次新的登录。具体实现积木见
[P6 个人用户认证前端交接](p6-authentication-handoff.md)。

2026-08-17 已实现上述第一批积木：统一错误模型保留可选 `code`、`X-Request-ID` 与 `Retry-After`；
共享 HTTP 层通过应用注入的会话失效事件连接 Auth Store 和 Router，仍保持 `shared` 不反向依赖具体业务；
公共认证布局与受保护工作台布局已经分离。2026-08-18 已完成真实后端、PostgreSQL、Mailpit、Vite 代理和
浏览器表单纵向联调。2026-08-18 已接入 F2-A 文档实体、运行时 DTO 校验、当前用户分页列表和单文件上传；
前端同时校验 `201 + duplicate:false` 与 `200 + duplicate:true` 的组合，重复内容作为可用的已有记录显示，
不按文件名判断，也不在浏览器承担并发唯一性。F2-B 已增加详情、独立 ProcessingJob 实体、无重叠任务轮询、
ready 后 chunks 分页和删除二次确认；任务终态只触发重新读取文档，不由界面伪造文档状态。
批量导入进一步把上传编排拆为独立队列：单路 Worker 分块哈希、上传前预检、有限并发上传、集中观察任务、逐项失败与重试，
并继续以后端上传哈希和数据库唯一约束为最终判重来源。完整结构与刷新恢复边界见
[F2-B 文档操作闭环](f2b-document-lifecycle.md)，批量状态机见
[F2 批量导入与解析队列](f2-batch-import-queue.md)。简单真实批次已验收，固定样本性能与双用户隔离仍待专项。

### 5.1 性能与背压责任边界

当前前端性能基线：

```text
哈希并发 1（Dedicated Worker，4 MiB 分块）
上传并发 2
批量状态刷新每轮最多 4 项、默认间隔 2 秒
单文档任务轮询默认间隔 1.5 秒，使用递归 setTimeout 避免重叠
```

这些数值是当前保守客户端策略，不跟随后端 `DOCUMENT_WORKER_CONCURRENCY` 或 Python 进程池大小自动变化。
后端扩容不构成提高浏览器并发的理由；浏览器并发只能通过固定样本的端到端延迟、CPU、内存和错误率评估后调整。

统一错误层已经保留 `X-Request-ID`、`Retry-After`、429 和 503。独立向量化页面已使用单一调度器、最多 4 路查询并发，
页面隐藏时暂停轮询并在恢复可见后立即同步；文档导入队列目前仍使用固定轮询间隔。2026-08-23，向量化和问答已接入
正式容量 code、单一可取消倒计时和到期后的手动重试；批量 200 中的容量项也能与已成功项隔离。仍未统一实现：

- 指数退避与抖动；
- 文档导入页面不可见时降低轮询频率；
- 后端容量恢复后的自动继续。

这些属于下一阶段背压体验优化，必须依赖正式错误 code 和接口语义。实现时仍保持单项失败隔离，不把暂时饱和标成永久业务失败。

前端性能验收至少分开记录：

- `hash_ms`：浏览器本地摘要；
- `preflight_ms`：预检网络和服务端查询；
- `upload_ms` 与上传字节数；
- `ready_visible_ms`：后端终态到页面显示终态的延迟；
- 429/503 次数、重试成功率和用户主动停止成功率。

开发观测不得记录文件正文、Session、完整摘要或跨用户数据。统一性能目标和压测口径见
[高性能与高并发工程目标](../../shared/architecture/performance-engineering-goal.md)。

## 6. 页面与视觉结构

第一版采用桌面优先的研究工作台：

```text
左侧导航 / 文档范围
        ↓
中间主工作区：文档库、搜索或问答
        ↓
按需出现的右侧来源面板
```

视觉基线为简约、克制、专业、内容优先：中性色、细边框、充分留白、少阴影和少量语义色。
Element Plus 只用于弹窗、分页、选择器、消息等行为成熟的组件；页面框架、文档列表、答案和来源区域
保持项目自己的视觉表达。

## 7. 测试与质量策略

```text
类型检查
  → API/状态纯函数测试
  → 组件和 composable 行为测试
  → 页面集成测试
  → 真实后端端到端测试
```

- Vite 负责转换和构建，类型检查必须由 `vue-tsc` 单独执行；
- Vitest 验证状态转换、错误转换和纯逻辑；当前 35 个测试文件、138 个测试通过；
- Vue Test Utils 验证组件渲染和用户交互；
- Playwright 在 F5 验证上传、处理、搜索和问答主流程；
- 测试优先断言用户可观察结果，不依赖组件内部实现细节。

## 8. 当前非目标

- Nuxt、SSR 和 SEO 架构；
- 微前端、跨端框架和多包工作区；
- GraphQL 或替换现有 REST 契约；
- 完整照搬大型 FSD/DDD 前端规则；
- 自建通用组件库；
- 把所有数据放入 Pinia；
- 为简历而提前引入未被真实需求使用的技术。
