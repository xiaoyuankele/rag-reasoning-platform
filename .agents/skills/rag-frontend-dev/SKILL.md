# Outcome

交付满足验收标准的最小前端切片，不静默扩大范围、改变共享契约或重构无关功能。

# Inputs

开始前确认目标、非目标、任务基线、允许写入路径和可观察验收标准。
跨域任务还必须具有冻结 Contract；缺失或不一致时退回 `rag-feature-flow`。

# Workflow

1. 读取适用的仓库规则、Contract、相关前端文档、附近实现和测试。
2. 检查当前行为、工作树、用户已有改动和允许路径。
3. 寻找最接近的现有 feature 模式，设计满足验收标准的最小切片。
4. 保持 `app → pages → features → entities → shared` 的依赖方向，但只引入任务实际需要的层级。
5. 将 HTTP 调用放在现有 API 边界；执行运行时 DTO 检查与边界转换，不在前端发明后端状态、
   权限、错误语义或调度规则。
6. 将状态保存在最小共享范围，并为用户可观察行为补充或调整测试。
7. 先运行聚焦测试和类型检查，再根据风险运行现有 lint、格式检查、完整测试和构建。
8. 对照任务基线和允许路径检查实际 diff，报告结果和未运行检查。

普通组件、状态和 API 测试属于本 skill。负载、长稳、多实例或故障恢复验证交给
`rag-scale-test`；其发现的生产缺陷只有在主线重新分配范围后才由本 skill 修复。

# Boundary

前端责任域上限是 `web/**` 和 `docs/frontend/**`，实际写权限仅限任务允许路径。
`backend/**`、`ai/**`、`contracts/**`、`docs/shared/**` 和根级部署配置默认只读。

依赖与锁文件、共享 HTTP 层、认证、浏览器持久化、Router 全局行为、全局状态、
全局样式和构建配置属于前端保护面，必须明确列入范围。

如果需要改变 Contract、修改范围外文件、增加未批准依赖或触碰未批准保护面，立即停止写入，
提供证据、准确路径、前端内替代方案和影响，并退回 `rag-feature-flow`。

# Output

报告可观察行为、修改路径、验证证据、未运行检查、Contract 偏差和下一次交接。
跨对话任务需要持久化时，只写 `chatgpt/工作流/<task-id>/frontend-handoff.md`，不修改 `control.md`。
